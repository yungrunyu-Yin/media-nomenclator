# 媒体库自动重命名 Skill

把一个媒体库里的视频文件、外挂字幕、以及承载它们的目录，统一整理成**规范、可刮削、可长期维护**的形态：

- 让 TMDB / Jellyfin / Emby / Alist 等刮削器能正确识别作品、季、集
- 让文件名对人可读、对机器可解析
- 让外挂字幕与对应视频自动配对
- 让整个修改过程**可预览、可回滚、不丢文件**

> **核心原则：宁可不修改，也不要猜错。**
> 信息无法可靠确认 → 保持原样并标 `NEED_REVIEW`，绝不用猜测填空。

本项目把命名规则**配置化**：行为由 `naming-config.json` 决定，改配置即可改变规则，
一般无需改动本文件或脚本代码。

## 0. 规则速查

### 0.1 命名格式

| 作品类型 | 模板 |
|---|---|
| 剧集 / 动漫 / 综艺（单季） | `剧名.年份.SxxExx.「集标题」.扩展名` |
| 剧集 / 动漫（多季） | `剧名.年份.SxxExx.「集标题」.扩展名`，按 `第X季/` 分目录 |
| 电影 | `片名 (年份) 分辨率.扩展名` |
| 外挂字幕 | 与视频**完全同基名**，仅扩展名不同 |

```text
示例剧集.2021.S01E01.「示例集标题」.mkv
某部剧.2024.S01E02.mkv                  ← 无可靠集标题 → 省略整段
示例电影 (2010) 2160p.mkv
```

字段之间用半角 `.`；标题**单词之间保留一个空格**，不得用 `.`/`-`/`_` 连接。

### 0.2 语言口径

**剧名与集标题一律「中文译名优先」，不分语种、不分存放目录。**

```text
多方查证中文译名
        ↓
能可靠确认 ──→ 用中文译名
        ↓
确认不了   ──→ 退回该作品的官方发行名称（英文 / 原文）
```

- **禁止机器翻译**；译名必须来自可靠来源，不得自行拟译。
- **华语作品**的官方中文名即原名，直接采用，绝不为了统一格式转成英文。
- **不设「当次指令优先」例外**：任何作品都走同一条流程。
- 确认标准见 §1.2。

### 0.3 目录规则

| 情形 | 规则 |
|---|---|
| 作品主文件夹 | 改名为**该作品的正式片名**，**不带年份**、不带分辨率/集数/发布组 |
| 季文件夹 | 统一为 `第X季`（阿拉伯数字，如 `第1季`、`第12季`） |
| 单季作品 | **不建季文件夹** —— 点开作品目录直接就是各集 |
| 多季作品 | 按 `第1季/`、`第2季/` … 分 |
| 多季合集主文件夹 | 用**系列母剧名**，不用某一季的季名 |
| 番外 / 特别篇 / 花絮 / 幕后 / SP / Special / OVA / OAD | **整体不动** |
| 分类层目录（如 `剧集/`、`动漫/`、`电影/`） | **不动** |

### 0.4 技术信息

| 作品类型 | 技术信息写入策略 |
|---|---|
| 剧集 / 动漫 | **一个都不写** —— 文件名到「集标题」为止 |
| 电影 | **只写分辨率**，其余（来源/编码/位深/音频/声道/发布组）全部删除 |

历史格式（`[1080p][H.265]` 之类方括号包围的技术信息）已废弃，不再使用。
本地读不到可靠分辨率时标 `NEED_REVIEW`，**不补猜**。

### 0.5 安全底线（每次动手前默念）

1. **先 Dry Run，再执行。** 未获用户明确确认，绝不落盘。
2. **不覆盖、不删除、不转码、不移动**（唯一例外：§7.3 单季多余季目录的上移与空目录回收，须逐条确认）。
3. **不猜**：无法确认的项标 `NEED_REVIEW`；已存在的目标名标 `SKIPPED_CONFLICT`。
4. **只改名字**：视频与字幕的内容、时间轴、编码一律不碰。
5. **一项卡住不影响其他项**：存疑的单点暂停，已确认的照常处理。

## 1. 信息来源

### 1.1 主来源与补充来源

| 媒体类别 | 主要来源 | 补充来源 | 状态 |
|---|---|---|---|
| 剧集 / 电影 / 纪录片 / 综艺 | **TMDB** | 官方平台、官方字幕、豆瓣、维基等 | 已实现 |
| 动漫 | TMDB（过渡期）→ 计划切换为 **dandanplay** | TMDB、豆瓣、维基等 | 计划中，见 §9 |

补充来源按以下顺序查证：官方发行名称 / 官方平台 / 官方字幕 → 豆瓣 → Wikipedia → 其他可靠影视数据库。

### 1.2 采信门槛（按字段区分）

| 字段 | 门槛 |
|---|---|
| **中文剧名** | **不降门槛**：主来源给出中文名后，仍须 **1 个独立来源**印证（官方来源可直接采信）；冲突或无第二源 → 退回官方原名 |
| 年份 | 主来源**单源即可** |
| 季结构（几季 / 每季集数） | 主来源**单源即可** |
| 季名 | 主来源**单源即可** |
| 集标题 | 主来源**单源即可**（仍须排除占位编号与站点自拟描述，见 §1.4） |

> ⚠️ TMDB 的 `zh-CN` 与 `zh-TW` / `zh-HK` **同属 TMDB**，不能互相印证。
> ⚠️ 冲突处理：除「中文剧名」外一律以主来源为准；中文剧名冲突则退回官方原名，**不猜**。

### 1.3 多季剧集与续集（易错）

**判定依据是数据源条目的季结构，不是「看起来像不像同一部」。**

判断顺序 —— 先查母剧条目的季列表，而不是先去搜续集的名字：

1. 定位母剧条目，读出它一共几季、每季的季名、各季首播年与集数。
2. 逐季取三样：**该季季名**、**该季自己的首播年**、**该季在系列中的季号**。

细则：

- **剧名 = 该季的正式季名**，不是母剧名；该季没有独立季名时才退回母剧名。
  - 季名在数据源上可能只写后半段（如「西行」「长安」），此时**补上系列前缀**成正式片名。
- **年份 = 该季自己的首播年**（不是母剧首播年）。
- **季号 = 该季在系列中的序号**，不重置。

**硬性检查：**

1. 你选定的条目下**必须真的存在**你写的那个季号，否则刮削查无对应季、直接失败。
2. 季名要**去条目里读**，不要自己起名，也不要只截后半段。
3. 该剧的季文件夹名同步改为 `第X季`（§7.2）。
4. **电视台/发行方分季 ≠ 数据源分季；两者冲突时一律以数据源为准**（刮削是最终目的）。
   此时文件名里的「季」标签与实际播出季不一致是**刻意**的。
5. **同一部剧可能存在重复条目**（母剧条目 + 孤立的单季条目）→ **以母剧条目的季结构为准**，
   忽略孤立条目，否则会把同一部剧的两季拆成两部剧。
6. **外挂字幕的集号必须一并换算**：字幕发布组常按**实际播出季**编号，而视频已按数据源单季编号
   → 此时不能照抄字幕自带的 `S0xEyy`，必须整体顺延（`前序各季集数之和 + n`），
   并在改名后**抽样读字幕正文**核对剧情与集号。两侧口径必须一致。

### 1.4 集标题

优先顺序：主数据源条目 → 官方平台 / 官方字幕 → 豆瓣 → Wikipedia → 其他可靠数据库。

取法：按顺序取**第一个真正给出集标题的来源**的标题，并在 Dry Run 里注明来源。

**必须排除两类假标题：**

1. **占位编号**（`Episode 1` / `第1集` / `EP05`）→ 视为**没有标题**；
2. **聚合站 / 影评站自拟的分集描述** → 不算集标题，不采信，也**不算来源冲突**。

语言口径同 §0.2（**中文优先，不分语种**）：

```text
可靠中文集标题  →  用中文
        ↓
可靠英文集标题  →  用英文
        ↓
都无可靠标题    →  省略集标题段
```

**绝对禁止**：机器翻译集标题 / 按剧情自行编写 / 为填满文件名强行加入不存在的标题。
**确无可靠来源时省略整段**，不写空 `「」`。

## 2. 文件名格式细则

### 2.1 电影

```text
片名 (年份) 分辨率.扩展名
```

- 年份用**半角括号**，前面一个空格：` (2010)`；片名与年份之间是**空格**，不是点号。
- 分辨率紧跟年份之后，中间一个空格；**分辨率之后即为扩展名**。
- 来源（BluRay / WEB-DL）、编码、位深、音频、声道、发布组**一律删除**。
- 读不到可靠分辨率 → `NEED_REVIEW`，不猜。

```text
示例电影 (2010) 2160p.mkv
Example Movie (2019) 2160p.mp4
Sample Film (2011) 1080p.mkv
Demo Movie (2022) 2160p.mkv
```

### 2.2 剧集 / 动漫

```text
剧名.年份.SxxExx.「集标题」.扩展名
```

**集标题之后不再写任何内容** —— 没有来源、没有分辨率、没有编码、没有音频、没有位深。

```text
示例剧集.2021.S01E01.「示例集标题」.mkv
Example Drama.2020.S01E01.「The Opening」.mkv
Sample Anime.2019.S01E01.「第一话标题」.mkv
示例剧集.2021.S01E30.mkv          ← 无可靠集标题时省略该段
```

### 2.3 集标题的引号

- 集标题**一律用全角直角引号 `「」` 包裹**，如 `「示例集标题」`。
- 引号是标题的一部分，**不得省略**；也不得改用 `《》`、`“”` 或半角 `"`。
- 引号**不计入**「集标题是否存在」的判断：先拿到标题，再包引号。
- 标题内部原有标点原样保留（如 `「序章 + 超级斯巴达 I」`）。

### 2.4 英文标题

英文标题由多个单词组成时：**保留单词之间的一个空格**、每个单词**首字母大写**。
同一标题内部**禁止**用 `.` `-` `_` 连接或强行合并单词。

```text
正确：Sample Show Name / Example Long Title / Another Show Name
错误：SampleShowName / ExampleLongTitle / Another.Show.Name / Another-Show-Name
```

**字段分隔与单词分隔必须区分**：字段之间用 `.`，单词之间用空格。
`Sample Show Name.2008` ✓ ｜ `Sample Show Name . 2008` ✗

### 2.5 中文标题

中文标题正常使用中文，**不人为增加空格**：`示例剧集.2021.S01E01…`，而非 `示例剧集 . 2021 . S01E01`。

### 2.6 年份

使用作品**正式上映、首播或发行年份**。
**不使用**下载年份、文件创建年份、当前年份、文件夹修改年份。
同名作品较多时年份尤其重要。

### 2.7 季数与集数

```text
S01E01 / S01E02 / S02E01
多集合并文件：S01E01-E02
特典：S00E01
```

**不得写成** `1x01`、`01-01`、`EP01`、`Episode01`（除非原始资源本身确实需要保留特殊编号）。

### 2.8 扩展名

视频原始扩展名**必须保留**（`.mkv`→`.mkv`、`.mp4`→`.mp4`、`.avi`→`.avi`、`.mov`→`.mov`），
**不得因重命名而转换格式**。字幕同理（`.ass`→`.ass`、`.srt`→`.srt`）。

## 3. 文件系统安全规则

Windows 禁止文件名包含：`\ / : * ? " < > |`

遇到时的处理顺序：

1. 优先根据可靠来源寻找合法写法；
2. 若只是来源中的特殊标点，采用不影响影视识别的安全形式；
3. 不得因非法字符导致整个批处理失败；
4. 无法安全判断时标 `NEED_REVIEW`。

**全角冒号「：」不算非法字符，一律保留** —— 只禁半角 `:`。
例：`某剧2：副标题.2014.S02E01.mp4`

## 4. 外挂字幕

支持 `.ass` `.srt` `.ssa` `.sub` `.vtt` `.smi`（只改文件名，**内容与时间轴一律不动**）。

### 4.1 必须与视频完全同名

```text
视频：示例剧集.2021.S01E01.「示例集标题」.mkv
字幕：示例剧集.2021.S01E01.「示例集标题」.ass
```

字幕基名必须与视频**完全一致**（含 `「」`），唯一允许不同的是扩展名。

### 4.2 禁止添加语言后缀

不要使用 `.zh` `.zh-CN` `.chs` `.cht` `.en` `.eng` `.ja` `.ko`。
刮削器靠「同名」配对，不靠语言标记。

### 4.3 冲突处理

- 同一视频存在**不同扩展名**的字幕（`xxx.ass` + `xxx.srt`）属正常，可分别保留。
- 同一基名存在**多个同扩展名**字幕，或改名后会产生冲突 → 标 `NEED_REVIEW`。
- **不得自动添加** `(1)` `(2)` `new` `copy`，也不得自行添加语言后缀来消解冲突。

### 4.4 语言策略：只保留简体，但有铁律

```text
同一集有多语言字幕
        ↓
该集 ① 有简体字幕 且 ② 另有非简体版本（繁体/双语/英文/日文…）
        ↓                                    ↓
   删掉非简体，只留简体              没有简体替代 → 原样全部保留
```

- **能删的条件必须两条同时满足**：该集确实存在简体字幕（`chs`/`sc`/`zh-CN`/`简`/`简中`/`简体`），
  且同时存在非简体版本。
- ★ **铁律：该集没有简体字幕时，一个都不许删。** 「只查到繁体就删掉」= 用户没字幕可看，是严重错误。
- **多个简体版本**：保留同一基名，自第 2 个起在扩展名前追加序号（`.2`、`.3` …）。
  这是「不得自动加序号」的唯一例外。
- **分不清语言就保守处理**：无语言标记的字幕无法确证是简体 → **一律保留**。
- **删除一律走云端回收站**（普通删除，非永久删除），且必须：先列清单 → 默认 dry-run → 用户确认。
  删除入口被隔离在独立的 `delete_list.py`，且只接受**字幕文件**或**完全空的目录**。

### 4.5 内封字幕：判断「有没有字幕」不能只看目录

**「目录里没有外挂字幕」≠「没有字幕」** —— 大量剧集把字幕**封在容器里**（内封/软字幕）。

判断顺序：**① 先看容器内字幕轨 → ② 再看同目录外挂字幕 → ③ 两者都无才算「真正缺字幕」。**

常见形态：`S_TEXT/ASS` + `chi 简体中字`、`S_HDMV/PGS` + `简体中文字幕`、`S_TEXT/UTF8` + `Simplified`。

- 只读探测工具：`probe_tracks.py`（读文件头，**不下载视频正文**）、`audit_subs.py`（逐集审计）。
- ⚠️ **内封字幕一律不动**：不改、不提取、不替换。本 Skill 只负责**文件名**，不碰容器内容。
- 同一部剧不同来源版本差别可能极大 → **必须逐集探**，不能抽样推断。

## 5. 工作流程（严格按序）

### Step 1 扫描

扫描目标目录中的视频文件、外挂字幕、子目录、已有命名信息。

⚠️ **分页必须翻完**：任何按页返回的接口，**条数恰好等于页大小就几乎一定还有下一页**，
必须继续直到返回空数组。判「缺集」绝不能用模糊搜索下结论，必须逐页扫全后按集号核对。

### Step 2 建立视频—字幕对应关系

依据原文件名、所在目录、季数、集数、扩展名、文件名相似度判断字幕归属。
无法确定 → `NEED_REVIEW`，不得猜测。

**成对核对法**（比逐条看更可靠）：统计该目录下视频数与字幕数，按「去掉扩展名后的基名」分组，
要求每组恰好 = {视频扩展名, 字幕扩展名}；有多余扩展名或落单的组 → `NEED_REVIEW`。

### Step 3 识别影视作品

确定：电影 / 剧集 / 动漫 / 纪录片 / 综艺，以及正式片名、年份、季数、集数。

### Step 4 查询数据源

按 §1 的顺序查证。取 TMDB 数据走 `src/sources/tmdb/tmdb_api.py`（见 §14.2），
不要一页页抓网页 —— 一次调用即可拿到完整季结构与全部集标题。

### Step 5 确定集标题

按 §1.4 的「中文 → 英文 → 省略」链条执行，**禁止机器翻译**。

### Step 6 读取技术信息

读取视频实际 MediaInfo，确认来源、分辨率、动态范围、编码、位深、音频、声道。
按 §0.4 决定写入哪些字段（剧集不写、电影只写分辨率）。
**读不到就不写，不补猜。**
文件夹名里的分辨率声明（如「4K」）属资源自带标注而非实测，是否采用**必须先问用户**。

### Step 7 生成重命名计划

先输出 `OLD → NEW` 对照，再进入 Dry Run。

## 6. Dry Run 是强制步骤

真正修改文件之前，**必须**先输出 Dry Run；**用户确认后**才允许执行。

### 6.1 输出位置

**Dry Run 默认只在对话里内联呈现**，不往工作区写 `.txt` 文档。
（大计划可由脚本写 JSON 计划文件，那是执行器的输入，不是给用户看的报告。）

### 6.2 内联 Dry Run 必须包含

文件一多（几十上百条）逐条罗列没有意义，按此结构给摘要：

1. **命名模板**：本任务实际生效的版本
2. **规模表**：每个季目录的文件数（视频 / 字幕分列）
3. **前后对照样例**：每季或每类挑 1–2 条 `OLD → NEW`，覆盖所有命名变体
4. **查证来源**：剧名与集标题取自哪个来源（含单来源标注）
5. **需用户拍板的点**：任何取舍、存疑项、`NEED_REVIEW` / `SKIPPED_CONFLICT`
6. **状态**：`READY` / 待确认

小批量（十几条以内）可直接逐条列出 `OLD → NEW`。

## 7. 目录与结构

```text
单季作品：
剧名/
├── 剧名.年份.S01E01.「集标题」.mkv
├── 剧名.年份.S01E01.「集标题」.ass     ← 字幕与视频同基名
└── ...

多季作品：
剧名/
├── 第1季/
│   ├── 剧名.年份.S01E01.「集标题」.mkv
│   └── ...
├── 第2季/
│   └── ...
└── ...
```

### 7.1 作品主文件夹

- 目标名 = **该作品的正式片名**，语言口径同 §0.2。
- **不带年份**、不带分辨率/集数/发布组/英文名/来源标签等任何附加信息。
- **多季合集**用系列母剧名；**单季作品**用片名本身。
- **绝不动的**：分类层目录及其上层根目录、番外/特别篇类目录。
- **只重命名主文件夹本身**，不移动、不增删其内部的季文件夹与文件。
- 执行前先列「当前名 → 目标名」清单交用户确认；作品身份无法可靠确认时标 `NEED_REVIEW`，不动。

示例：

```text
示例剧集[全12集]Sample.Show.2020.WEB-DL.2160p.H265.AAC-GROUP  →  示例剧集
示例剧集 1080P                                                →  示例剧集
Sample.Show.Name                                              →  示例剧集
```

### 7.2 季文件夹

- 统一为 `第X季`（阿拉伯数字）：先确认是第几季，再把各种写法折算 ——
  `Season01` / `S01` / `Season 1` / `Season.01` → `第1季`；季标题式命名 → 折回季号。
- 去掉季目录名里的年份、括号、分辨率/画质标签（`第1季（2009）4K` → `第1季`）。
- **季号必须依据可靠数据源确认**，不能按目录出现顺序猜。
- **只重命名目录本身**，不移动、不改动、不删除目录内任何文件。
- 跳过的目录：番外 / 特别篇 / 特别集 / 花絮 / 幕后 / `Special(s)` / `OVA` / `OAD` / `SP`。

### 7.3 单季作品的多余季目录（唯一允许「移动」的场景）

历史上若把单季作品放进了 `第1季/` 目录，应把集文件**上移**到作品目录，并清掉那个**已空**的目录。

- 前提：已用可靠数据源确认该作品**确为单季**。
- 移动用 `conflictPolicy=skip`（绝不覆盖）；删除空目录走 `delete_list.py`（递归确认为零文件才允许）。
- 全程需用户确认。

## 8. 技术信息字段（历史参考）

> §0.4 之后，剧集**不写**技术信息、电影**只写分辨率**。下表保留作历史参考，供将来需要恢复时使用。

| 字段 | 取值 |
|---|---|
| 来源 | `WEB-DL` `WEBRip` `BluRay` `BDRip` `REMUX` `HDTV` `DVD` |
| 分辨率 | `2160p` `1080p` `720p` `480p` |
| 动态范围 | `SDR` `HDR` `HDR10` `HDR10+` `DV` `Dolby.Vision` `HLG` |
| 视频编码 | `H.264` `AVC` `H.265` `HEVC` `AV1` |
| 位深 | `8bit` `10bit` `12bit` |
| 音频 | `AAC` `AC3` `DD` `DD+` `DDP` `DTS` `DTS-HD.MA` `TrueHD` `Atmos` `FLAC` |
| 声道 | `2.0` `5.1` `7.1` |

字段顺序：`来源.分辨率.动态范围.编码.位深.音频.声道`。

**两个已知坑**：

1. **声道号 `5.1` / `7.1` 内含点号**，与字段分隔符冲突 —— 不先保护会被切成 `5` + `1` 而丢失。
2. **编码 `H.264` / `H.265` 内部也含点号** —— 同样需保护，否则被切成 `H` + `265`。

`techinfo_reorder.py` 已内置这两道保护，并有自测用例覆盖。

**不要过度堆砌**：文件大小、平均码率、GOP、色彩空间、色度采样、编码器版本、音频采样率、
封装器版本等一律不写 —— 只保留对识别、筛选、人工查看有明显价值的信息。

## 10. 存储后端

命名规则与后端无关；后端只负责 I/O。

### 10.1 本地目录 / Alist 挂载

用文件系统扫描与重命名。

### 10.2 CloudDrive2（gRPC API）

媒体库若经 CloudDrive2 挂载为盘符（如 `F:`），**不要在挂载盘上做 rename / move / mkdir**
（WinFsp 本地语义开销大），改为直连 CloudDrive2 的 gRPC API。

- 协议：**gRPC over HTTP/2**；端口自动从 CD2 的 `config.toml` 读取，读不到则回退 `19798` / `29798`。
- 认证：gRPC metadata `authorization: Bearer <API_TOKEN>`；令牌只从环境变量或独立文件读取。
- 路径：令牌带 `root_dir` 时，**API 路径必须相对该 root_dir**，不能照搬云端全路径。
- 缓存：改后校验必须 `forceRefresh`，否则可能读到旧目录列表。
- 执行器内置硬护栏：**任何带盘符、反斜杠或 UNC 的路径一律中止**，从源头保证不落挂载盘。
- 冲突策略固定 `skip`，**绝不 overwrite**。
- 本通道**明确不提供**：删除、上传、下载、内容写入、转码、NFO / 海报生成。
  唯一例外是清理自检产生的空目录（`cleanup_testdirs.py`，限死白名单 + 递归零文件校验）。

### 10.3 网盘 MCP

通过网盘类 MCP 接口扫描与重命名时同理：分页必须翻完，
冲突策略用 `fail` / `skip`，**绝不用 `overwrite`**。

## 11. 冲突与不确定信息

| 情形 | 标记 | 动作 |
|---|---|---|
| 目标文件名已存在 | `SKIPPED_CONFLICT` | **不覆盖**，保留原文件并报告冲突 |
| 作品 / 年份 / 季数 / 集数 / 集标题无法确定 | `NEED_REVIEW` | **保持原样**，交用户判断 |
| 多个候选作品可能匹配 | `NEED_REVIEW` | 交叉核对后交用户确认 |
| 字幕无法确定对应视频 | `NEED_REVIEW` | 不动 |
| 多个文件会产出同一目标名 | `NEED_REVIEW` | 不动 |

**不得**：覆盖、删除原文件、自动添加 `(1)`/`(2)`/`new`/`copy`。

## 12. 禁止操作

本 Skill 只负责**安全重命名与整理**。禁止：

删除视频 / 删除字幕（§4.4 的受限删除除外）/ 覆盖已有文件 / 修改视频内容 / 修改字幕内容 /
修改字幕时间轴 / 修改字幕编码 / 转码 / 压缩 / 裁剪 / 合并 / 分割 / 移除原始文件 /
未经用户确认直接批量执行。

---

## 13. 最终原则

目标不是让文件名「看起来最复杂」，而是：

> **让人容易看、让机器容易识别、让字幕容易匹配，并尽可能降低自动重命名出错的风险。**

优先级：

```text
准确性 → 刮削兼容性 → 字幕匹配 → 可读性 → 技术信息完整度
```

- 信息无法可靠确认 → **不猜**，标 `NEED_REVIEW`
- 目标文件已存在 → **不覆盖**，标 `SKIPPED_CONFLICT`
- 只是为了让文件名看起来更完整 → **不加没有可靠依据的信息**
