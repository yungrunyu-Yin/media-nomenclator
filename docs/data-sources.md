# 数据源

数据源负责**识别作品身份**与**获取元数据**。它们**只读**，不参与任何文件写入。

---

## 1. 总览

| 数据源 | 提供的东西 | 角色 | 状态 |
|---|---|---|---|
| **TMDB** | 作品身份、年份、季结构、季名、分集标题、地区别名 | 剧集 / 电影 / 纪录片 / 综艺的**主来源** | **已实现** |
| 官方发行名 / 官方平台 / 官方字幕 | 中文译名、分集标题 | **权威单源**（可直接采信） | 已实现（查证流程） |
| 豆瓣 | 中文译名、分集标题 | 补充来源 | 已实现（查证流程） |
| Wikipedia | 中文译名、分集标题 | 补充来源 | 已实现（查证流程） |
| **dandanplay 开放 API** | 动漫作品识别、剧集匹配 | 计划中：动漫的**主来源** | **尚未接入**，未获权限 |

> 数据源可以**按媒体类别**选用不同的主来源，但命名**格式**规则始终全库统一 ——
> 「按类别换来源」不等于「按目录换规则」。

---

## 2. 采信门槛（按字段分层）

不是所有字段都用同一套标准，这是刻意的设计：

| 字段 | 门槛 | 理由 |
|---|---|---|
| **中文剧名** | **不降门槛**：主来源给出中文名后，仍须 **1 个独立来源**印证（官方来源可直接采信）；否则退回官方原名 | 剧名是文件名的门面，也是最容易被机翻污染的一环 |
| 年份 | 主来源**单源即可** | 客观、不易歧义 |
| 季结构（几季 / 每季集数） | 主来源**单源即可** | 刮削以数据源结构为准 |
| 季名 | 主来源**单源即可** | 同上 |
| 集标题 | 主来源**单源即可**（仍须排除占位编号与站点自拟描述） | 大量剧集只有单一站点收录集名，硬要第二源会导致全部省略 |

**同一数据源内的多语言变体不算独立来源**：TMDB 的 `zh-CN` 与 `zh-TW` / `zh-HK` 同属 TMDB，
不能互相印证。

**冲突处理**：除中文剧名外一律以主来源为准；中文剧名冲突则退回官方原名，**不猜**。

## 3. 已实现：TMDB

### 3.1 用途

作品身份 / 年份 / 季结构（季号 · 季名 · 该季首播年 · 集数）/ 分集标题 / 地区别名。

### 3.2 方式

走官方 **API v3**，而不是逐页抓网页。好处：

- 一次调用即可拿到**完整**季结构与**全部**集标题（抓网页容易只返回最后一集）
- 不受页面改版影响
- 可机器消费（`--json`）

### 3.3 命令

```bash
python src/sources/tmdb/tmdb_api.py selftest                # 自检：密钥 / DoH / 连通 / 业务查询 / 占位识别
python src/sources/tmdb/tmdb_api.py search tv "剧名"         # 搜剧，拿候选条目 id
python src/sources/tmdb/tmdb_api.py search movie "片名" --year 2010
python src/sources/tmdb/tmdb_api.py tv <id>                 # 季结构表
python src/sources/tmdb/tmdb_api.py season <id> <季号>       # 该季全部集标题（中英对照）
python src/sources/tmdb/tmdb_api.py movie <id>              # 电影详情
python src/sources/tmdb/tmdb_api.py titles tv|movie <id>    # 别名与地区译名
python src/sources/tmdb/tmdb_api.py raw /tv/<id> --json     # 任意端点原样输出
```

### 3.4 内置的两个实用机制

**① 占位标题识别**
`season` 命令会自动把 `第N集` / `Episode N` 这类**占位编号**标出来，省去人工逐条辨认。
纯数字（如 `737`、`51`）是**真实**集标题，刻意不标占位。

**② DNS 污染的 DoH 绕行**
当系统 DNS 把 `api.themoviedb.org` 解析成错误 IP 时，直连必然超时。
脚本的做法是：**先用 DoH 取真实 IP，再用「固定 IP + 正确 SNI」建 TLS** ——
既绕开污染，又**保持证书校验**（不关 `verify`）。解析结果按 TTL 缓存。

### 3.5 密钥纪律

密钥只从环境变量 `TMDB_API_KEY` 或 `~/.config/media-nomenclator/tmdb_api_key` 读取。
**不写入仓库、不写入配置文件、不打印到日志** —— 脚本只回显掩码。

### 3.6 API 不可达时

退化为网页抓取兜底，并在 Dry Run 里**注明降级原因**。

## 4. 补充来源（人工查证流程）

当主来源缺失、或需要为中文剧名找独立印证时，按顺序查：

1. 官方发行名称 / 官方平台 / 官方字幕 —— **给出中文名即可直接采信**
2. 豆瓣 —— 尤其中文影视
3. Wikipedia
4. 其他可靠影视数据库或权威媒体资料

**纪律**：

- 禁止机器翻译，禁止自行拟译
- 聚合站 / 影评站自拟的分集描述**不算集标题**，也不算「来源冲突」
- 查到的结果要在 Dry Run 里注明**取自哪个来源**，方便用户否决

## 5. 计划中：dandanplay

### 5.1 定位与动机

dandanplay 开放 API 计划作为**动漫**媒体识别与剧集匹配的**数据源之一**，
用于辅助确定动漫作品及具体剧集信息。

**动机**：本项目的直接动因是下游的弹幕匹配。下游服务（例如兼容弹弹play 接口规范的弹幕 API 服务器）
会从**文件名**里解析作品名、季号与集号，再据此做标题比对与季集解析 —— 文件名不规范时匹配就会失配，
轻则取不到弹幕，重则匹配到错误的剧集。动漫正是最容易失配的类别（别名多，季集划分在不同资料库间
经常不一致），所以需要一路动漫向的数据源作交叉验证，提高动漫文件命名的准确率，
从而让下游能对准正确的剧集。

> ⚠️ 边界：本项目只负责把**名字**改对，**不获取、不存储、不分发弹幕**，也不含任何弹幕数据。

### 5.2 使用场景

| 场景 | 说明 |
|---|---|
| 动漫作品识别 | 从杂乱的动漫文件命名中定位作品身份（含中文名与原始名） |
| 剧集匹配 | 确定某集属于哪一季、第几集，辅助季集结构与分集标题的确认 |

### 5.3 接入后的影响范围

**仅动漫类别**：动漫的主来源由 TMDB 切换为 dandanplay，TMDB / 豆瓣 / 维基降为补充来源。
其余类别（剧集 / 电影 / 纪录片 / 综艺）不变。
**中文剧名的第二源门槛不因换源而取消。**

### 5.4 当前状态（重要）

- **尚未**获得 dandanplay API 权限
- 仓库内**没有任何** AppId / AppSecret / API Key
- 仓库内**没有** dandanplay 的调用代码，也**没有**任何调用结果
- dandanplay **不是**本项目的驱动者；本项目**不是** dandanplay 的客户端或替代品
- 不包含、也不计划包含：弹幕数据、播放器功能、账号体系、社区功能

### 5.5 接入时要遵守的约定

1. **只读**：只发 GET，绝不写远端数据
2. **凭据独立存放**：放用户配置目录，不入仓库、不入配置、日志只回显掩码
3. **自带 `selftest`**：像 TMDB 通道一样，一条命令即可判断通道是否可用
4. **失败给降级说明**：不可达时明确说明并退回补充来源，而不是静默编造
5. **差异先出报告**：季集结构与现有库不一致时，先出 Dry Run 交用户拍板，**不自动改**
6. **先试点一部验收，再逐部推进**，不在一批里全库改造

## 6. 新增数据源的接口约定（计划）

目标是把「新增一个数据源」变成只加一个适配器文件。约定四项能力：

| 能力 | 输入 | 输出 |
|---|---|---|
| `search` | 片名 / 剧名（可带年份） | 候选条目列表（id + 名称 + 年份） |
| `detail` | 条目 id | 作品身份、年份、原始名 |
| `seasons` | 条目 id | 季列表（季号 / 季名 / 该季首播年 / 集数） |
| `episodes` | 条目 id + 季号 | 分集列表（集号 / 标题 / 是否占位） |

外加两条纪律：**密钥不入库不入配置**；**只读**。

> 目前只有 TMDB 一个适配器是完整实现的；上述注册机制仍在规划中。
